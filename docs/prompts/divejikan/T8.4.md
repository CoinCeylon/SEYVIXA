## Steps

1. Plan mode first.
2. Take one simulated, validly signed receipt from `tools/verifier/fixtures/` (generated from demo data only).
3. Change one field from a list: `locked_lovelace`, `total_lkr`, `outcome`, or `release_tx_id`. One field per run. The script never signs again.
4. Write the altered copy to a new file. Never overwrite the original.
5. Run the verifier CLI on the copy with the trusted fingerprint. Show its output. The expected result is `REJECTED`.
6. Print a short plain message: "Altered field X; verifier result REJECTED." No key material.
7. Tests:
   - each listed field, altered, gives REJECTED
   - the untouched receipt still gives VERIFIED (control)
   - the original file is unchanged after the run (hash compared)

## Acceptance criteria

- P0-7: the altered receipt is REJECTED for every field in step 3 (test).
- The original receipt is not modified (test).
- The untouched receipt gives VERIFIED (control test).
