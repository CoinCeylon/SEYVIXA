## What to fix (from the review)

1. **`--write-env` accepts any path.** `--write-env .env.example` would put the real private key into a file that git tracks. Fix: accept only a path whose file name is exactly `.env` and that `git check-ignore` reports as ignored. Refuse everything else with a plain error that does not print the key.
2. **The script can overwrite the real private key.** The overwrite guard looks only at the public file, so `--write-public <temp file> --write-env <real .env>` replaces the real key and the published key then no longer matches the server. Fix: if the env file already has a value for `RECEIPT_SIGNING_PRIVATE_KEY` that is not the placeholder `REPLACE_ME_...`, refuse, whatever other flags are given.
3. **A missing `--write-env` value is silently ignored.** The script then generates a key, discards the private key and still writes the public file. Fix: require `--write-env <path>` (fail closed), reject unknown flags, and reject a flag with no value. Write the env file first and the public file second, and never touch the public file if the env write fails, so a failure cannot leave a mismatched pair.
4. **`--force` replaces the published public key.** This breaks "do not regenerate after publication". Recommended fix: remove `--force` completely. Rotation is a separate decision for Abdul and a separate card. Abdul confirms this in the plan review.
5. **Over-claims in the script header and README.** The header says "Writes ONLY the public key". The README says the private key "stays in server `.env` only". File mode `0o600` has no real effect on Windows and none on a file that already exists. Fix: reword to say exactly what happens: the script writes the private key to the one file you name, only if it is an ignored `.env`; the mode setting does not protect the file on Windows; protecting the file is the owner's job.
6. **README refers to a second publication that does not exist.** It says "and from the submission slide/documentation" but nothing is published there yet. Fix: remove that reference. Blueprint 6.8 needs a second independent place (slide, video or submission document). That is Abdul's job and the T8.2 criterion stays open until he has done it. Do not claim two places.
7. **No tests cover the script's safety rules.** Add the tests below.
8. **Optional check.** The "no private field" test checks key names and a few patterns. Add one more: no string value in the public file looks like a PKCS#8 base64url private key (starts with `MC4CAQAwBQYDK2VwBCIEI`).
9. **Env var name and format.** `RECEIPT_SIGNING_PRIVATE_KEY` holds a PKCS#8 DER private key in base64url. This is not in `DECISIONS.md`. Do not edit `DECISIONS.md` (Abdul writes it). In the PR, state the name and format in one line, and say whether T8.1 (receipt generator) reads the same name and format (check the T8.1 card or code). If they differ, stop and tell Abdul.
