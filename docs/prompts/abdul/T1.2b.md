## Goal

Store an immutable action record, with a server-computed canonical payload and action hash, when evaluate returns `ALLOW` or `APPROVAL_REQUIRED`. Bind the budget reservation by setting `actions.reservation_id`.

### Blueprint Section 6.5 (Exact Purchase Approval, binding and canonical action)

~~~~markdown
Create a canonical representation of the action and calculate its hash.
Bind approval to:

-   Owner (user), taken from the authenticated session
-   Supplier/payee
-   Items and quantity
-   Amount and currency
-   Action hash
-   Expiry
-   One-time nonce

If any material field changes, the approval is invalid and must be
requested again. The gateway rechecks the approval and policy at
execution time (Section 6.2).

**Canonical action.** The server builds one immutable action record and computes `action_hash = SHA-256(canonical JSON)`, using a deterministic canonical form (sorted keys, no extra whitespace, UTF-8, for example RFC 8785). The record contains the procurement ID, owner ID, supplier/payee, items and quantity, the simulated LKR total, the settlement asset (`tADA`) with a fixed demo escrow amount as a separate field, the escrow script address, the refund deadline, the expiry and the nonce. It has no LKR-to-ADA conversion field. The agent never supplies the hash.
~~~~

## Steps

1. Plan mode first.
2. Build the canonical payload on the server from stored data (procurement, quote), never from agent-supplied fields. The agent never supplies the hash.
3. `action_hash = SHA-256(canonical JSON)` using the shared helpers. The record is immutable: changing any material field creates a new action and a new hash.
4. Generate `commitment_salt` (32 random bytes) when the action is created. It never goes on-chain.
5. Set `actions.reservation_id` when evaluate binds a reservation (decision D2b).
6. Status (decision D15): `APPROVAL_REQUIRED` creates the action with `PENDING_APPROVAL`; `ALLOW` without approval creates it as `APPROVED`; `DENY` creates no action record (only `policy_events`). A verified approval moves `PENDING_APPROVAL` to `APPROVED` (that is T2.3, not here).
7. Store `actions.policy_version` = the current `POLICY_VERSION` constant (decision D16).
8. Tests: identical payload gives an identical hash; the agent cannot supply the hash; a changed field gives a new hash.
