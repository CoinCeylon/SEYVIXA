### Blueprint Section 6.1 (Owner and agent identity)

~~~~markdown
**Owner and agent identity.** The demo owner authenticates to a server-side session (for example a seeded login using the framework's standard session handling, with an HttpOnly session cookie). Every owner request derives `owner_id` from that session. Any `owner_id` in a request body or URL is ignored or rejected, and every owner-scoped query filters by the session's owner ID. The owner's approval public key is registered on the owner record at setup. Agents authenticate with their own agent credentials, never with the owner session, and can never approve.
~~~~

## Steps

1. Plan mode first. Use the framework's standard session handling. Login is not counted as a product API.
2. Seeded login for the demo owner (credentials from `.env`, fake values in `.env.example`). HttpOnly session cookie.
3. `getSessionOwnerId(req)` returns the owner id from the session or fails closed. Keep the exact signature the stub has.
4. Replace the stub in T1.1b and T1.6 with this function. Delete the stub code. It must be gone before 5 Dec.
5. Any `owner_id` in a body or URL is ignored or rejected. Owner-scoped queries filter by the session owner. For `supplier_quotes` and `budget_reservations`, use the shared owner-scope query helper created in T1.6 (decision D27); do not write a second one.
6. Tests: forged `owner_id` ignored or rejected; no session gives failure; an agent credential is not an owner session.
