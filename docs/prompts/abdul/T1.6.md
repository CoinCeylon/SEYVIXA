### Blueprint Section 7 (rules for all endpoints)

~~~~markdown
All endpoints that change state must authenticate the caller (owner
session or agent credential), derive owner identity from the session,
enforce idempotency where appropriate, and record an audit event.
`POST /api/actions/execute` is the only endpoint that may invoke a
protected connector or submit a blockchain transaction. The three escrow
endpoints only prepare unsigned transactions. Each requires an
`action_id` that has been evaluated, builds the transaction from the
stored action (never from request fields), and returns it for the owner's
wallet to sign. The wallet signs but does not submit. The signed
transaction goes to `/api/actions/execute`, which checks it against the
stored action and submits it. Escrow lock, release and refund are
therefore ordinary protected action types (`ESCROW_LOCK`,
`ESCROW_RELEASE`, `ESCROW_REFUND`) that pass through the same
evaluation, approval and execution boundary. Login uses the framework's
standard session handling and is not counted as a product API.
~~~~

### Blueprint Section 9 (item 10)

10. **Owner authentication and isolation:** Owner identity comes only

~~~~

## Steps

1. Plan mode first.
2. All three routes derive `owner_id` from `getSessionOwnerId(req)` (a stub until T2.1 lands; remove the stub before 5 Dec, decision D19). A body or URL `owner_id` is ignored or rejected. Every query filters by the session owner. `supplier_quotes` and `budget_reservations` have no `owner_id`: create one shared query helper (for example `apps/api/src/db/owner-scope.ts`) that joins `procurements` on `owner_id`, and use it for every read and write of those tables (decision D27). Policy events are found with `policy_events.procurement_id` (D27).
3. `GET /api/procurements/:id` returns the request, workflow status, the agents' permissions, the policy decision log, and the budget summary from `getBudget(procurementId)`. Until Prabhath's T4.3 lands (30 Nov) use a clearly marked stub. Do not add any route.
4. `POST /api/quotes` stores a supplier quote (stored content is untrusted data).
5. Write an audit event for each state change. Define response types in `packages/shared` and tell Shahnas.
6. Tests: another owner's procurement is not readable; forged `owner_id` ignored.
